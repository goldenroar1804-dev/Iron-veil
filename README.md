# IRON VEIL

Native Meta Quest tactical PvE prototype built with Godot 4 and OpenXR.

## Current prototype features
- OpenXR head and controller tracking
- Smooth thumbstick locomotion and turning with swept capsule collision checks and wall sliding to prevent walking through static structures
- Start-of-mission rifle pickup from a stand; grip-button pickup/drop and trigger firing
- Detailed procedural M4-style carbine, separate tracked human-shaped hands, and randomized indoor CQB targets
- Expanded suburban block with eight enterable house shells, parked vehicles, and static collision on architecture and vehicle props
- Procedural sky, ambient lighting, fog, and subtle surface variation
- Three layered transparent muzzle-flash sprite cards generated at runtime
- CC0 rifle-shot and concrete-footstep MP3 effects downloaded and cached on first launch

## Free asset sources
- Kenney City Kit (Suburban), CC0: https://kenney.nl/assets/city-kit-suburban
- OpenGameArt muzzle-flash PNG pack, CC0: https://opengameart.org/node/179598
- SFXMint rifle shot and concrete footsteps, CC0: https://sfxmint.com/sounds/impact-gunshot-08 and https://sfxmint.com/sounds/footsteps-concrete-75

The current prototype generates its muzzle-flash sprite locally and downloads the two CC0 audio effects on first launch. The Kenney and OpenGameArt packs are listed as future art-source options; their model/sprite files are not yet bundled in this repository.

## Open the project on Quest 3
1. Download this repository as a ZIP from GitHub and extract it with a Quest file manager.
2. Import the extracted folder into Godot on Quest.
3. Confirm OpenXR is enabled and run the project.
4. Allow the app to access the internet on first launch so it can fetch the CC0 sound effects. The audio files are cached locally after a successful download.

The first goal is to verify the scene launches correctly in the headset. APK export and the required Android build environment are a separate step.

## Important testing note
This is an early prototype. The latest visual and audio changes have not been tested on a physical Quest headset by the developer. Internet access is required for the first audio download. If the downloads fail, the project will log a warning and the corresponding sound will be silent until the download succeeds.



## Latest weapon visual pass
The M4-style carbine is assembled from detailed lightweight meshes, including an adjustable stock, buffer tube, split receiver, ejection-port detail, quad-rail handguard, barrel, birdcage flash hider, optic, magazine, and trigger guard. The right glove uses rounded palm/finger segments positioned around the pistol grip. The muzzle effect uses three overlapping transparent flame sprites and a short light pulse. These are procedural meshes and generated sprites, not imported photogrammetry or commercial asset models.


## Latest gameplay and collision pass
The rifle now starts on a pickup stand and only attaches to the right controller after the player reaches it and squeezes the grip button. Both hands are independent of the rifle and follow their respective tracked controllers. Buildings, roads, sidewalks, fences, props, and parked-car bodies have static collision geometry; wheels have separate collision shapes. Front window panes and trim are kept clear of the central house entrance so they do not obstruct the doorway. The map is extended along the street and each of eight houses receives one to three randomized CQB targets inside its room. Hand meshes remain procedural approximations rather than imported scanned human-hand assets; the current repository still does not bundle third-party environment model packs.


## Collision correction
Smooth locomotion now checks a standing capsule against physics bodies before moving the XR origin. When a direct movement path is blocked, the controller attempts separate horizontal-axis movement so the player can slide along walls instead of passing through them. Static architecture and vehicle colliders are generated by the environment builder. This is a code-level correction that still needs an in-headset Quest 3 test.

## Visual realism status
The current environment, weapon, and hands are still procedural prototype geometry. This update does not claim photorealistic models or imported scanned assets. The next art pass needs proper smooth, rigged hand models, a detailed weapon asset, and authored suburban building/vehicle assets with PBR materials; primitive meshes alone cannot deliver the requested realism.


## Latest graphics and doorway pass
Moved the second front window and its trim to the right-side wall section so the front doorway remains an unobstructed opening. The window panes remain static collision objects. This fixes a visible doorway obstruction in the previous layout. The current meshes are still prototype geometry; no claim of photorealistic assets is made. A dedicated asset-import pass is needed for high-quality hands, weapon, architecture, and vehicles.


## Grass rendering
The ground grass is a flat generated color texture with subtle mottled variation tiled across the terrain. No individual grass blades, raised tufts, or grass geometry are generated, keeping the surface flat and Quest-friendly.


## Surface material pass
The shared material detail tile now uses seamless broad mottling plus finer grain, with closer texture tiling and roughness/metalness tuned by material color. This improves surface breakup on the existing procedural scene without adding high-resolution texture memory. It does not replace the primitive weapon, hand, house, or vehicle meshes; those remain a separate modeling task.


## Optional imported Godot assets (latest update)
The project now supports an optional imported M4-style GLB at `res://assets/models/weapons/m4_carbine.glb`. When present, it replaces the procedural rifle mesh while preserving the existing pickup, firing, muzzle-flash, and controller-attachment logic. If the GLB is absent or cannot load, the procedural rifle remains the fallback.

Bundled rifle and concrete-footstep audio can now be placed at `res://assets/audio/rifle_shot.ogg` and `res://assets/audio/footsteps_concrete.ogg` (WAV and MP3 are also accepted). Local audio is preferred; the existing CC0 download-and-cache behavior remains the fallback.

See [assets/ASSET_IMPORT_GUIDE.md](assets/ASSET_IMPORT_GUIDE.md) for exact paths, scale/orientation requirements, suggested free asset sources, license-recording guidance, and Quest optimization notes. House, vehicle, and hand models are still procedural; their imported overrides are not wired yet. No third-party model files are bundled by this code update, and the imported-model path still needs a headset test.
